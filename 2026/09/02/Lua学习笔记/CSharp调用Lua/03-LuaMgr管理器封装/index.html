C# 调用 Lua:LuaMgr 管理器封装

前两课直接在场景脚本里 new LuaEnv() 用,但项目里一般会封装成一个管理器(单例),统一管理解析器的生命周期,并提供执行 Lua 脚本、读取 Lua 变量等接口。这一课就是封装思路。

关键点

Global 属性

luaEnv.Global 对应 Lua 中的 _G 总表,后面 C# 读取 Lua 里的全局变量、函数都要通过它:

Init 只初始化一次

防止重复创建解析器,保持唯一性。初始化时注册了两个 Loader:

  • MyCustomLoader:从 Application.dataPath + "/Lua/" 目录读取 .lua 文件
  • MyCustomABLoader:通过 AB 包管理器加载 Lua 脚本资源(适合热更)

DoLuaFile 封装 require

把 require('文件名') 封装成一个方法,以后加载脚本只需传文件名。

空判处理

DoString / Tick / Dispose 都做了 luaEnv == null 的判断,解析器未初始化就提示并返回,防止空引用。

小结

  • 用单例 BaseManager<T> 封装 LuaMgr,保证解析器唯一。
  • Global 拿到 _G,是 C# 读写 Lua 变量的入口。
  • Init / DoString / DoLuaFile / Tick / Dispose 各司其职。
  • 双 Loader:普通目录加载 + AB 包加载,适配本地资源和热更资源。
